# 朝の株ウォッチ

- スケジュール: `CRON_TZ=Asia/Tokyo 22 8 * * 1-5`
- 毎回新しいセッションで実行、スマホ通知あり、環境はデフォルト
- `<記録帳のURL>` は、実際の指示文ではトレード記録帳のURL（Artifact の list で探す）

## 指示文の要点（2026-11-21 時点）

この控えは要点だけ。動いている指示文の全文は、スケジュールの get_trigger で読む（ここに全文を写すと古くなるため。2026-11-21 に要点だけに変えた）。`<記録帳のURL>` は実際にはトレード記録帳のURL。

- 記録帳の settings/main、trades（open・plan）、signals（PENDING）を読む。
- kabu-lens.mjs で、前営業日の企業の行動（`--buyback`）、保有と候補の日足、PTS、保有株の適時開示（`--tdnet`）、決算日、世界の状況（`--world`。notes と、11/21 からの日経平均先物 nkFut＝CME の円建て先物の今の値と日経平均の終値との差）を取る。
- 資金の下げの歯止め（capitalPeak から ddStopPct% 以上下げていれば新しい買いを入れない）。先物が大きく下げていても企業の行動の寄指は取り消さない（11/21 の検証）。
- 通知（12〜18行）：1行目、①入れる注文（企業の行動・スイングの候補最大2件・損切り未設定・保有期限）、②確認すること（逆指値と利確が入っているか・開示・決算・PTS）、③今日の上限と世界の状況（現金・損の合計の空き・下げ%・米国・先物・notes）、最後に「最終判断はご自身で」。記録帳には書き込まない。
- **11/27 変更（本人の希望：朝と夜で入れる注文が違うのは困る）**：①入れる注文は、夜の点検が保存した settings/order_plan（for_date が今日）をそのまま出す。株数・値段・どれを入れるかを朝に計算し直さない。足すのは PTS の注意だけ。order_plan が無ければ「夜の注文票を確認できず」として新しい注文を出さない。trades の status が plan（本人の予定）は「【本人の予定】◯◯◯株：note のとおり」と夜と同じ1行。前営業日の `--buyback` と signals からの計算はやめた。
