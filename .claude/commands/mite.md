対象: $ARGUMENTS

1銘柄の「いつ買うか」を、3つの期間でまとめて見る。判定はスクリプトに任せ、自分で条件を足したり緩めたりしない。断定的な推奨はしない。

1. 銘柄名しか無いときは、記録帳に同梱の universe-wide.json か株探でコードを確かめる（分からなければ本人に聞く）。
2. トレード記録帳（Artifact の list で題名「トレード記録帳」を探す）のデータベースを ArtifactData で読み、/kau と同じ形の状態ファイルをスクラッチパッドに作る（settings/main、trades の open。`frozen: true` は positions に入れない。date が今日の記録の数が buysToday）。
3. 同じデータベースから settings の intraday_wide_stats・cands_stats・backtest を get し、スクラッチパッドのフォルダに `<名前>.json` で書く（無いものは書かない）。業績の判定のファイル（少し長期）があれば、それも使う（下の4）。
4. `node .claude/scripts/kabu-lens.mjs --mite <コード>[:今の値段] --state <状態ファイル> --stats-dir <フォルダ>` を実行する（本人が楽天の画面の今の値段を言ったら必ず `:値段` を付ける。業績の判定が使えるときは `--long <ファイル>` も）。
5. 次の形で、短く伝える（数字は結果のまま。取れなかったものは「確認できず」）。
   - 1行目：「◯◯（コード） 今◯円」と、3つの判定を1行で（例：デイトレ 待つ／スイング 買い候補（押し目）／少し長期 準備中）。
   - **デイトレ（場中・5分足）**：判定、何時時点か（15〜20分遅れ。今の値段を添えたなら「今の値段で判定し直し」）、場中の流れ、VWAP、理由。買い場なら指値の目安と場中の損切りの目安。近い支えと壁を1つずつ。record（成績）をそのまま。marks があればその説明。
   - **スイング（数日〜数週間・日足）**：判定と形、見送りなら理由、翌営業日に買うなら「◯円以下なら指値」（buy_below）、損切り・目標・最長◯営業日。record（成績）をそのまま。「どの日に買っても平均◯R」という比べる相手を必ず添える。
   - **少し長期（数か月）**：verdict と、200日線の上か下か・傾き、52週高値からの位置、週足の向き、次の決算日、株が増える資金調達の注意。fundamentals があれば、その要点と成績。
   - **買う前チェック**：止める理由（blocks）があれば最初に「このチェックでは買わない判定です」と書いて並べる（抜け道は示さない）。無ければ株数・金額・損切り・損失額。注意（warnings）を並べる。
   - 最後に1行：「合図の上乗せは小さく、外れる日も多い。損切りと株数で守る。最終判断はご自身で」。
6. 記録帳の considered に1件 set する（/kau と同じ形。source: "mite"、decision は blocks があれば "blocked"、無ければ "passed"）。場中の判定（day）は /bachu と同じく intraday にも1件残す（name は日本語の銘柄名）。
7. 本人が見たいと言ったら、day.bars からチャートを描いて見せてよい（ローソク足・VWAP・支えと壁）。
